# 数据语义与存储边界

## 数据层次

系统分别保存原始输入、求解意图、最终发布命令、发布 receipt、设备反馈、
相机观测与会话/停止/错误事件。它们不能混用作训练动作标签。

- 原始手柄输入是操作意图；连续 trigger、二值决定和目标开口具有不同含义。
- 最终发布目标是经过映射/IK/执行检查后交给驱动的目标。
- receipt 可以表示已发布，不一定是电机执行 ACK。
- 实际关节/夹爪反馈是观测，不能假装成操作者希望执行的动作。
- 原生末端 Euler、驱动转换 Quaternion、FK 派生位姿分别保存 provenance。

## 文件与协议

| 范围 | 版本/布局 |
| --- | --- |
| M1 fake | 0.3.0-m1，固定 graph/event schema，MCAP |
| 多端点 fake | collection-plan/1、collection-event/1 |
| WebXR 输入 | webxr-input/1；不同网络传输复用输入语义 |
| 真实 episode | real-episode/1 原始图像；real-episode/2 可包含 RGB MP4 |
| 工作流 | workflow-session/1，当前为明确支持的 native 绑定 |

真实 episode 通常包含 `manifest.json`、`streams.mcap`、`index.jsonl`、对齐/质量信息，
MP4 后端另有每路 RGB 视频与逐帧媒体索引。清单记录流、配置、计数、哈希及状态。
具体布局由 schema 与读取模块验证，不应仅按扩展名猜内容。

图像索引保留流名、序号、原始源时间、接收时间与媒体帧/PTS 引用。
深度保留原始整数、宽高、编码与行步长；未确认比例时不能默认为毫米，
也不能把未做光学校准的深度宣称成 RGB 注册图像。

## 时间与单位

主机单调时间用于本机顺序与信息年龄，Unix 时间用于外部标识，设备时间属于其
显式时钟域。MP4 PTS 为编码/播放时间，不替代采集时间。
不能直接相减不同主机的 monotonic 时间推算单程网络延迟；RTT 与端到端画面延迟分开度量。

通用关节使用 rad，位置/开口使用 m；原生 SDK 字段保留原单位与原始值。
Quaternion 顺序、Euler 约定、参考 frame、TCP 与关节顺序必须写明。
未知值保留 unknown/null，不默认为零、单位阵或某个机器人约定。

## 写入与审阅

回调只向有界队列提交，磁盘线程处理媒体与 MCAP。
停止关闭新的接收窗口后排空已接收数据，完成编码器和文件，再计算 QC。
原始时间戳不在 QC 中改写；对齐结果是消费视图，不声称硬件同步曝光。

保存与任务成功标签是不同决策。frame gap、缺流、过期状态、队列溢出、
截断文件或未知动作目标应在质量/来源信息中表达；不能为了使 QC 通过补造观测。

训练出口与可视化工具由独立适配选择字段、重采样与格式。
本仓库提供读取/因果训练视图，不随公开源码携带任何私人数据集或转换结果。
